# Content Quality Rules V3.3

## Purpose

These rules define the V3.3 editorial review standard for Explore plans generated by `travel-content-pipeline`.

This is a quality rule document only.

It does not:

- modify code
- modify schema
- modify prompts directly

V3.3 focuses on the quality gap still visible after Beijing V3.2 testing:

- missing travel themes
- weak active trade-off
- insufficient food experience depth
- unstable memory points
- AI-template-like expression

## Core Review Shift

V3.2 mainly asks:

- Is this plan more vivid and premium?

V3.3 asks:

- Does this plan feel like a real travel editor made a clear choice?

That means a strong plan is not only richer.
It is more opinionated, more selective, more theme-led, and more motivation-aware.

## 1. Core Travel Proposition

Every plan must have one clear travel proposition.

This is the answer to:

- what is the strongest reason to choose this trip

It should be expressible in one sentence.

Examples:

- a first-time Beijing route that builds the city's strongest impression without exhausting the user
- a hutong-and-lakes weekend that favors texture and atmosphere over landmark completion
- a food-first short trip where meals are part of the destination, not route filler

### Pass signal

- theme is visible from title, summary, and itinerary
- route choices all serve the same proposition
- the plan has a recognizable reason to exist

### Risk signal

- title says one thing, route does another
- the plan mixes too many motives at once
- the core idea could be swapped with many other plans

## 2. Active Trade-Off Logic

A premium plan must choose.
It must not try to satisfy every possible desire.

This is the most important V3.3 addition.

The plan should make visible trade-offs such as:

- fewer landmarks for better rhythm
- fewer districts for stronger depth
- one stronger dinner instead of three generic food mentions
- one iconic sunset slot instead of overpacked late afternoon routing

### Required review question

Can the reviewer clearly see what this plan intentionally did not optimize for?

### Pass signal

- some popular options are omitted for a reason
- route density reflects a real editorial decision
- the plan protects its strongest moments from dilution

### Risk signal

- everything important is vaguely included
- route reads like a compromise list
- every day tries to do too much

## 3. Daily Storyline

Every day must have a story arc, not just a schedule.

A daily storyline should answer:

- how the day begins
- what experience it builds toward
- what emotional note it ends on

### Suggested daily arc types

- strong opener -> layered middle -> memorable close
- slow local beginning -> major anchor -> relaxed night finish
- daytime exploration -> evening payoff
- one dense highlight block -> one release block

### Pass signal

- the day has emotional progression
- the ending feels earned
- activities are sequenced for experience, not just map logic

### Risk signal

- the day is a flat list
- morning, afternoon, and evening can be reordered with no loss
- no clear climax or closing memory

## 4. Food Experience Rules

Food is no longer a support note only.
It is part of the trip's identity.

### Core rule

At least one meal or food moment should feel worth planning around.

Food should contribute in one of four roles:

- local daily-life entry point
- destination-worthy meal
- atmosphere amplifier
- route recovery and pacing support

### Food quality standard

A strong food recommendation should imply:

- why this meal matters in this route
- what kind of experience it offers
- what to eat or what style to prioritize
- when it is best inserted into the day

### Pass signal

- dining is integrated into the route logic
- food creates desire, not just practicality
- snacks, meals, and setting have differentiation

### Risk signal

- only broad cuisine labels
- meals feel replaceable
- food exists only because every plan is expected to mention it

### Failure pattern to avoid

- nearby local food is available
- lunch can be arranged freely
- dinner is left open without editorial reason

These are structurally weak unless the plan is intentionally minimal.

## 5. Travel Editor Voice

The writing should sound like a travel editor guiding a reader, not like a model filling fields.

### Voice requirements

- selective
- concrete
- lightly opinionated
- useful without sounding rigid
- descriptive without over-performing lyricism

### Good voice traits

- explains why a choice is good in this plan
- acknowledges trade-offs naturally
- gives practical insight with editorial confidence
- uses city texture instead of empty praise

### Bad voice traits

- generic admiration
- exaggerated emotional slogans
- repetitive recommendation formulas
- explanation that sounds detached from real travel behavior

### Voice test

A reviewer should feel:

- someone is making decisions for me
- this is not stitched together from attraction notes
- this route feels like it could really be walked

## 6. AI Template Expression Limits

This section exists to directly suppress template-like output.

### Expressions to reduce sharply

- empty praise
- repeated "very suitable" style recommendation phrases
- repeated sentence openings
- generic emotional claims without scene support
- summary, POI, and daily text saying the same thing three times

### Structural repetition to reduce

- every day using the same rhythm sentence
- every POI using the same reason template
- every restaurant using the same recommendation formula
- every plan ending in the same emotional conclusion

### Required anti-template standard

The plan should contain visible variation in:

- sentence rhythm
- justification style
- memory framing
- food description
- day closing language

### Reviewer question

If city names are replaced, would this still sound like the same template?

If yes, the item fails.

## 7. Memory Point Stability

A strong plan should leave stable memory anchors.

Each day should ideally give the user at least one of the following:

- one moment worth remembering
- one image worth stopping for
- one city-life detail worth retelling
- one meal worth mentioning afterward

### Pass signal

- the reviewer can retell each day in one sentence
- the day has a non-interchangeable memory point
- memory points fit the plan theme

### Risk signal

- memories are vague or generic
- all memory points sound visually similar
- food, route, and mood do not reinforce one another

## 8. Updated Review Dimensions

A V3.3 review should focus on these dimensions:

### 1. Theme clarity

Does the plan have a strong core proposition?

### 2. Editorial selectivity

Does it actively choose rather than try to include everything?

### 3. Storyline quality

Does each day build toward a meaningful experience?

### 4. Food depth

Does the food layer create real travel desire or decision value?

### 5. Memory strength

Are the memorable points stable and specific?

### 6. Natural editorial voice

Does the writing sound human, useful, and non-template-like?

### 7. City and traveler fit

Does the plan still stay credible for the destination and audience?

## 9. Suggested Failure Tags V3.3

- unclear travel proposition
- weak active trade-off
- flat daily storyline
- thin food experience
- unstable memory points
- template-like copy
- weak city texture
- weak traveler fit
- route is valid but not premium
- other

## V3.3 Pass Standard

A strong V3.3 Explore plan should satisfy most of the following:

- one clear travel proposition
- visible active trade-offs
- daily storyline rather than flat scheduling
- at least one worthwhile food experience
- memorable moments that can be retold
- editorial voice instead of AI template voice
- city and traveler logic still intact

If the plan is executable but still feels like:
"reasonable, complete, but without a soul"
then it has not passed the V3.3 standard.
